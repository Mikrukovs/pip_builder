# Деплой WebSocket сервера на production

## Быстрое решение проблемы

Если вы видите ошибку `Cannot find module '/app/server.js'`, выполните на сервере:
```bash
cd ~/projects/pip_builder
git pull origin dev
docker-compose down
docker-compose up -d postgres app-dev
```

## Что изменилось

1. Добавлен кастомный Node.js сервер (`server.js`) для поддержки WebSocket
2. Добавлена библиотека Socket.IO для real-time collaboration
3. Изменены скрипты запуска в `package.json`
4. Добавлена система гидратации в auth store для предотвращения мелькания
5. Создан отдельный layout для редактора

## Обновление на сервере

### 1. Подключитесь к серверу
```bash
ssh deploy@85.198.109.41
```

### 2. Перейдите в директорию проекта
```bash
cd ~/projects/pip_builder
```

### 3. Получите изменения из Git
```bash
git pull origin dev
```

### 4. Остановите контейнеры
```bash
docker-compose down
```

### 5. Запустите контейнеры с новой конфигурацией
```bash
docker-compose up -d postgres app-dev
```

Контейнер автоматически установит новые зависимости (socket.io) при старте.

### 7. Проверьте логи
```bash
docker-compose logs -f app-dev
```

Вы должны увидеть строки:
```
=== Installing dependencies ===
added 19 packages...
=== Starting dev server with WebSocket ===
> Ready on http://localhost:3000
```

**Примечание**: Если контейнер уже был запущен и вы видите ошибку "Cannot find module '/app/server.js'", просто перезапустите его:
```bash
docker-compose restart app-dev
```

## Проверка работы WebSocket

1. Откройте проект в редакторе
2. В консоли браузера должно появиться: `Socket connected`
3. В правом верхнем углу редактора должен отображаться индикатор "Онлайн" (зеленая точка)
4. Откройте тот же проект в другом браузере/вкладке
5. Счетчик активных пользователей должен обновиться

## Устранение проблем

### WebSocket не подключается
1. Проверьте, что порт 8888 открыт на сервере:
   ```bash
   sudo ufw status
   ```

2. Проверьте логи:
   ```bash
   docker-compose logs --tail=100 app-dev
   ```

3. Проверьте, что контейнер запущен:
   ```bash
   docker-compose ps
   ```

### Мелькание экранов при обновлении
Это должно быть исправлено автоматически. Если проблема осталась:
1. Очистите кэш браузера (Ctrl+Shift+R)
2. Проверьте, что auth store правильно гидратируется

### Изменения не синхронизируются между пользователями
1. Откройте консоль браузера и проверьте ошибки
2. Проверьте, что WebSocket подключен (зеленая точка "Онлайн")
3. Попробуйте перезапустить контейнер:
   ```bash
   docker-compose restart app-dev
   ```

## Важные моменты

- WebSocket использует тот же порт, что и основное приложение (8888)
- Путь для WebSocket: `/api/socket`
- Аутентификация через JWT токен
- Каждый проект имеет свою комнату для изоляции изменений
- Автосохранение срабатывает каждые 3 секунды и отправляет изменения через WebSocket

## Тестирование real-time синхронизации

1. **Подготовка**: Обновите проект на сервере (см. выше)
2. **Откройте проект в двух браузерах**:
   - Браузер 1: Войдите под одним пользователем
   - Браузер 2: Войдите под другим пользователем (или в режиме инкогнито)
   - Откройте один и тот же проект в обоих браузерах

3. **Проверьте синхронизацию**:
   - В браузере 1: Добавьте компонент на страницу
   - ✅ В браузере 2: Компонент должен появиться через ~500мс
   - В браузере 2: Измените текст в компоненте
   - ✅ В браузере 1: Текст должен обновиться через ~500мс

4. **Проверьте индикаторы**:
   - ✅ Счетчик должен показывать "2 участника онлайн"
   - ✅ Зеленая точка "Онлайн" в обоих браузерах
   - ✅ В консоли: "Received update from user: [userId]"

## Как работает синхронизация

1. **Локальные изменения**: При любом изменении проекта (добавление/удаление компонентов, изменение свойств) изменения отправляются через WebSocket после 500мс debounce
2. **Получение изменений**: Когда другой пользователь вносит изменения, они приходят через WebSocket и применяются через метод `syncProject`
3. **Предотвращение эха**: Флаг `isSyncing` предотвращает повторную отправку полученных изменений
4. **Автосохранение**: Независимо от синхронизации, проект сохраняется в БД каждые 3 секунды
